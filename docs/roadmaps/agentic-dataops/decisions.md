# Decisions

- 2026-11-17 | horizon 1 | dlt syncs Verified Sources and PyAirbyte only Docker-free Community Sources, both behind one Sync port — because PyAirbyte runs source-postgres only via Docker (ADR-0012)
- 2026-11-17 | horizon 1 | Horizon 1 keeps all 7 phases so the demo loads end-to-end — because the user chose to see a working demo over a smaller foundations-only horizon
- 2026-11-17 | horizon 1 | Domain and application layers import no framework (dlt, dagster, typer, os.environ); engines sit behind Sync and orchestrator ports — because 100% branch coverage needs fakes
- 2026-11-17 | horizon 1 | No `pragma: no cover` except TYPE_CHECKING; secrets reach Dagster ops only by closure, never run config — because coverage and secret-safety must be real, not gamed
- 2026-11-17 | horizon 1 | Every Sync table gets built-in Checks; a failed Check stops later Steps; skipping needs a written reason (ADR-0013) — because every flow must be guarded
- 2026-11-17 | horizon 1 | Check verdicts come only from pure domain rules over SourceFacts/LoadFacts; adapters only measure — because same facts must give the same verdict
- 2026-11-18 | horizon 2 | Schema snapshots live in adops._adops_schema_snapshots in each Environment's Warehouse, saved only after every Check of the Step passes — because each Environment needs its own baseline
- 2026-11-18 | horizon 2 | An intended Breaking Change is accepted only via `adops accept-schema <pipeline> <table> --env`, never automatically — because schema changes must be a deliberate choice
- 2026-11-18 | horizon 2 | dbt runs through dbt-core's dbtRunner behind a Transform port, not dagster-dbt; dbt test failure counts are measured, verdicts stay in domain rules — because of ADR-0013
- 2026-11-18 | horizon 2 | Steps run in linear YAML order; 'downstream' means every later Step — because no Step graph exists yet
- 2026-11-18 | horizon 2 | Domain code never reads the clock; 'now' comes from an injected Clock port — because freshness verdicts must be deterministic
- 2026-11-18 | horizon 2 | Horizon 2 finishes the Check system only; horizon 3 does dbt Transform, then dedicated errors, then DuckDB — because the user chose that order
- 2026-11-18 | horizon 3 | Empty Source table is a built-in skippable Check source_not_empty raising EmptySourceTableError (a CheckFailedError) — because the user wants it to stop, but skippable with a reason
- 2026-11-18 | horizon 3 | The Transform engine is bound into its planned Step at plan build; StepTask and the Orchestrator stay unchanged — so no engine or credential travels through Dagster run config
- 2026-11-18 | horizon 3 | A dbt warn is a passing Check with a message; dbt tests get no skip_checks — because severity is already configured in dbt itself
- 2026-11-18 | horizon 3 | dbt-duckdb is a dev-only test stand-in so real-dbt unit tests run without Docker; dbt-core 1.12.7 and dbt-postgres 1.11.0 are runtime deps
- 2026-11-18 | horizon 3 | adops validate checks only that <project>/dbt_project.yml exists; it does not run dbt parse in horizon 3 — user choice
- 2026-11-18 | horizon 3 | Failed dlt loads get fixed sanitized messages ('load failed') and the dlt logger is silenced — fixed in horizon 3, not deferred
- 2026-11-18 | horizon 3 | DuckDB Warehouse moves to horizon 4 — horizon 3 holds dbt Transform plus dedicated errors, user kept both in one 6-phase horizon
- 2026-11-18 | horizon 4 | dlt[duckdb] and dbt-duckdb==1.11.1 are runtime dependencies; supersedes the horizon-3 'dbt-duckdb is a dev-only test stand-in' line — because installed users need DuckDB
- 2026-11-18 | horizon 4 | The Warehouse kind is a required argument of DltSync, WarehouseSnapshotStore and DbtTransform, read from the selected Environment — because a silent 'postgres' default hides wiring bugs
- 2026-11-18 | horizon 4 | A DuckDB warehouse is `type: duckdb` + `path`, relative to the Project unless absolute, with no secret; resolved as ResolvedDuckDb(path) — because ADR-0007 has nothing to resolve for a local file
- 2026-11-18 | horizon 4 | The demo stays Postgres by default and ships a commented DuckDB warehouse block; no new Environment or init flag — user choice
- 2026-11-18 | horizon 4 | The full Docker E2E scenario runs on both Warehouse kinds in one compose stack, reseeding the shop Source between runs; the 20-min CI timeout is not raised — user choice
